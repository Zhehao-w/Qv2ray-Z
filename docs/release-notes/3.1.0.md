# Qv2ray-Z v3.1.0

Qv2ray-Z 3.1.0 is a maintenance and compatibility release focused on modern Xray behavior, safer configuration round-tripping, fail-closed runtime boundaries, removal of obsolete legacy surfaces, and a reproducible Windows release pipeline.

## Highlights

- VLESS + TLS + Vision and VLESS + REALITY + Vision retained and regression-tested
- modern VLESS `encryption` values preserved verbatim across supported import/export and runtime generation
- REALITY ML-DSA-65 verification (`pqv` / `mldsa65Verify`)
- XHTTP and FinalMask support
- modern VLESS share-link import/export with opaque query preservation
- conservative preservation of imported, subscription-created, routing, transport, TLS, and protocol configuration data
- TLS certificate-pin validation at editor and kernel-start boundaries
- safer Windows process lifecycle, configuration startup, routing storage, and failure handling
- refreshed Windows desktop behavior for connection-list sizing, button feedback, System Proxy preferences, and Bypass CN tray state
- verified official bundled Xray-core and Geo routing assets
- authoritative Windows x64 build, test, install, package, and smoke-test pipeline

## Configuration and data safety

3.1.0 strengthens the boundary between fields Qv2ray-Z actively manages and data it should preserve without interpretation.

- unknown connection-root and outbound JSON is preserved through supported graphical edits
- VMess, Shadowsocks, HTTP, and SOCKS single-server editors apply managed deltas while preserving unknown settings, additional servers/users, and opaque fields
- unknown and nested transport fields are preserved
- unsupported stream-security metadata is not silently rewritten
- opaque TLS certificate fields are preserved
- unknown, duplicate, and raw VLESS query items are preserved across supported share-link round-trips
- routing and DNS saves preserve unmanaged auxiliary JSON, structured DNS servers, host arrays, FakeDNS data, and raw server identity where the editor does not own the data
- stale internal preservation metadata is stripped before runtime generation
- unsupported runtime-only legacy fields fail closed or are removed at the final runtime boundary
- persisted configuration is not destructively migrated just to satisfy cleanup work

Subscription refresh remains source-of-truth replacement. Preservation applies when an imported or subscription-created connection is subsequently opened and saved through the supported graphical editor; fields intentionally removed by the remote subscription source are not resurrected.

There is no automatic migration from unrelated legacy features to newer ones. For example, legacy HTTP transport is not converted to XHTTP, and legacy mKCP Header camouflage is not converted to FinalMask.

## Fail-closed and security hardening

Several paths that previously risked continuing with incomplete or unsafe state now reject the operation before mutating active runtime state.

- application startup fails closed when global configuration initialization fails
- malformed or unsupported share-link parsing fails closed instead of producing partially valid connections
- unsupported VLESS transports are rejected rather than silently mapped to another transport
- current TLS certificate pins are validated after opaque JSON restoration and again before kernel startup
- nested/effective XHTTP download settings are included in TLS pin validation
- unsafe TLS pin configurations are rejected before the active connection is stopped or a new generated configuration is written
- invalid or unreadable `routes.json` blocks routing-dependent startup instead of silently falling back to default routing
- routing/group storage failures preserve pending edits and selected state for retry rather than silently diverging from persisted data

## Modern Xray compatibility

The maintained Windows product supports the modern paths used by this project, including:

- VLESS, including opaque preservation of modern `encryption` values
- TLS
- REALITY
- Vision flows
- TCP
- WebSocket
- current mKCP fields
- gRPC
- XHTTP
- FinalMask

The pinned bundled Xray release for 3.1.0 is **v26.3.27**.

The Windows package also includes verified `geoip.dat`, `geosite.dat`, and `geoip-only-cn-private.dat` assets. Exact release-input versions and SHA-256 values are recorded by the release pipeline and emitted into `release-manifest.json`.

## Routing and proxy behavior

3.1.0 keeps one persisted source of truth for the routing and proxy preferences exposed in multiple UI surfaces.

- **System Proxy on Connect** is surfaced under Preferences → General and continues to control the existing automatic set/clear behavior during connection lifecycle changes
- tray **Enable System Proxy** / **Disable System Proxy** remain immediate manual commands and are intentionally separate from the persistent automatic preference
- tray **Bypass CN Mainland** is now a single checkable action backed by the same `bypassCN` state used by Preferences
- opening the tray refreshes the Bypass CN check state from the global configuration
- changing Bypass CN from the tray persists the same preference and, when already connected, reuses the existing restart path so routing takes effect
- simplified routing presets continue to preserve explicit custom Block / Proxy / Direct rule priority
- Mainland China routing uses the maintained GeoIP/GeoSite assets and optimized built-in bypass behavior

## Desktop UI polish

The Windows UI received a focused cleanup without changing protocol or proxy ownership semantics.

- fresh/default MainWindow launches provide more width to the Connection pane
- previously saved MainWindow geometry remains authoritative for existing users
- splitter persistence remains intentionally disabled
- connection rows use a stable 68px height so underscores and descenders such as `y`, `g`, and `p` are not clipped
- connection-item left/right spacing is more balanced
- neutral MainWindow buttons use consistent full-surface hover/pressed feedback
- semantic **New / Connect** blue and **Disconnect** red states remain distinct
- **Connect ↔ Disconnect** uses a stable minimum width to avoid horizontal layout jumps
- the relocated System Proxy checkbox participates in the General-page keyboard tab chain

## Legacy cleanup

This release removes or disables legacy surfaces that are no longer valid for the maintained product while keeping persisted compatibility where that remains useful.

- removed inactive Android build/service code
- removed historical Debian, Snap, and RPM packaging paths
- removed the obsolete MTProto outbound editor
- removed unreachable inbound placeholder editors
- disabled legacy QUIC transport creation/import/export and removed its unreachable UI
- disabled legacy HTTP / H2 / H3 transport creation/import/export and removed its unreachable UI
- disabled legacy mKCP Header camouflage and Seed handling and removed their unreachable UI
- removed legacy SSD (`ssd://`) share-link import

Current mKCP transport fields remain supported. FinalMask remains supported and is intentionally separate from retired transport/header camouflage.

Some historical persisted model fields remain in the codebase solely for backward-compatible loading. Their presence does not imply that they can be newly created or emitted to modern Xray runtime configuration.

## Windows reliability and release hardening

3.1.0 includes additional Windows lifecycle and release-path hardening:

- safer Xray process start/stop/failure behavior
- System Proxy, connection-context, data-safety, and routing safety regression coverage
- authoritative Windows x64 build with Qt 5.15.2 and MSVC 14.2
- pinned release metadata verification
- pinned dependency archive size / extraction validation
- official Xray binary verification
- verified `geoip.dat`, `geosite.dat`, and CN/private GeoIP assets
- Xray fixture validation before packaging
- packaged application smoke testing
- release build manifest containing source, Xray, Geo, Qt, and toolchain metadata
- explicit heavyweight `routing_ui_safety` validation on the native Windows Qt platform plugin

The dependency cache stores raw dependency archives only. Cache hits do not bypass pinned metadata, expected-size, extraction, or setup verification.

Linux CI remains diagnostic only. Windows x64 is the authoritative release target and release gate.

## Compatibility notes

- Existing supported configurations should continue to load without silent destructive mutation.
- Unsupported legacy features are not automatically rewritten into superficially similar modern features.
- JSON-editor changes remain authoritative; explicit JSON deletions are not merged back from stale preserved data.
- VMess remains incidental compatibility code and is not an active modernization target for this project.
- No broad protocol expansion is planned for this release line.
